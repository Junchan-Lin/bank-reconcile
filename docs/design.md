# 銀行入帳對帳：設計文件

- 日期：2026-10-16
- 狀態：已確認設計，待撰寫實作計畫
- 品牌：逅斯蓋工作室（Code Sky）作品集，作品 2（報表自動化）

## 1. 目的與情境

**客戶情境**：採用銀行轉帳收款的中小企業或電商，每週或每月要把銀行入帳明細和訂單一筆筆對起來，找出哪些訂單已收款、哪些還沒收、哪些金額不對，以及哪些入帳不知道是哪張訂單。人工比對費時又容易漏。

**這個作品要證明的事**：能把格式各異的 Excel／CSV 自動整理、比對，產出可直接交給會計的報表；對不確定的配對交給人判斷，而不是硬配。它對應服務方案「報表自動化」。

### 範圍

第一版包含：

- 上傳銀行明細與訂單檔（CSV、Excel），自動判斷編碼與表頭列
- 內建 2 種示範銀行格式與 1 種示範訂單格式；辨識不出時在網頁上指定欄位，並可儲存供下次自動辨識
- 三層配對規則，每筆結果附上依據
- 對帳結果頁：確認或排除待確認項目
- 下載 Excel 報表
- 保存對帳工作，到期自動刪除
- 虛構範例資料與「載入範例資料」按鈕
- Docker Compose 一鍵啟動

第一版不包含：

- 一筆匯款付多張訂單、一張訂單分多次付款（分別出現在「不明入帳」與「未收款」）
- 層級 ②、③ 的金額容差（例如客戶自行扣手續費 15 元）；只有層級 ① 會以「金額不符」標出差額
- 發票比對
- 登入與多使用者
- 直接串接銀行或電商平台 API

## 2. 架構

單一服務，所有處理都在本機進行，不連任何外部服務；銀行資料不離開這台主機。

```
瀏覽器 ──上傳銀行明細＋訂單檔──▶ bank-reconcile（port 8000）
                                 讀檔 → 辨識格式 → 正規化 → 配對 → 存成對帳工作
瀏覽器 ◀──對帳結果頁／Excel 報表──
```

### 2.1 元件

| 元件 | 職責 |
|---|---|
| `readers` | 讀取 CSV 或 Excel 成為表格（表頭＋資料列）；CSV 依序嘗試 UTF-8（含 BOM）與 Big5（cp950）；在前 10 列中找出表頭列（銀行匯出常在表頭上方有標題列） |
| `formats` | 格式設定：記錄各欄位對應哪一欄。內建格式寫在程式碼；使用者建立的存在資料庫。依表頭自動辨識 |
| `normalize` | 轉成統一的入帳（日期、金額、備註、帳號末五碼）與訂單（訂單編號、日期、金額、客戶、末五碼）。銀行明細只取存入金額 |
| `matching` | 純邏輯的分層配對，每筆結果附上依據 |
| `report` | 用 openpyxl 產生 Excel 報表 |
| `web` | FastAPI + Jinja2 伺服器端渲染 |
| 資料保存 | SQLite；保留天數到期自動刪除 |

## 3. 資料模型

| 資料表 | 欄位重點 |
|---|---|
| `FormatProfile` | 類型（bank / orders）、名稱、欄位對應（JSON）；辨識所需的欄名由欄位對應推導，不另外儲存 |
| `Job` | 建立時間、銀行檔名、訂單檔名、使用的格式名稱、日期容許天數 |
| `Deposit` | 所屬工作、原始列號、日期、金額、備註、帳號末五碼 |
| `Order` | 所屬工作、原始列號、訂單編號、日期、金額、客戶、末五碼 |
| `Link` | 所屬工作、入帳、訂單、類型（matched / mismatch / candidate）、層級（1–3）、依據說明、狀態（auto / pending / confirmed / rejected） |
| `SkippedRow` | 所屬工作、來源（bank / orders）、原始列號、原因 |

- 「有效配對」：`matched` 或 `mismatch`（狀態 auto），以及狀態為 confirmed 的 `candidate`。
- 「未收款訂單」：沒有有效配對、也沒有 pending 候選的訂單（還在待確認的訂單只出現在「待確認」）。
- 「不明入帳」：沒有有效配對、也沒有 pending 候選的入帳。
- 上傳的原始檔不保存，只保存解析後的資料。

### 欄位對應

- 銀行：日期（必要）、存入金額（必要）、備註（選填）、對方帳號（選填，取末五碼）。
- 訂單：訂單編號（必要）、日期（必要）、金額（必要）、客戶（選填）、匯款末五碼（選填）。
- 格式辨識：上傳檔的表頭包含某格式欄位對應的所有欄名，即視為該格式；使用者建立的格式優先於內建格式，同類中依建立順序。

## 4. 正規化

- 金額：移除「NT$」「$」「元」、千分位逗號與空白後轉成整數；空白或 0 視為沒有存入，該列不算入帳；無法解析則記為略過的資料列。
- 日期：支援 `2026-10-05`、`2026/10/05`、`20261005`，以及民國年 `115/10/05`、`115.10.05`；Excel 的日期儲存格直接使用。
- 末五碼：從對方帳號或回報欄位取出數字，取最後 5 碼；不足 5 碼視為沒有。
- 訂單編號比對時：轉大寫，並移除空白與連字號。

## 5. 配對規則

入帳依（日期、原始列號）由早到晚處理，同樣的資料每次結果相同。一筆訂單最多被確定配對一次，一筆入帳最多對到一筆訂單；前面層級用掉的資料，後面層級不再使用。

### 5.1 層級 ①：備註含訂單編號（完整詞比對）

- **切詞**：備註與訂單編號用同一套規則處理：NFKC 正規化（全形轉半形）、轉大寫，再以「英數字與連字號以外的字元」切成詞，每個詞去掉連字號。例如「#A1001」→〔A1001〕、「SO/1001」→〔SO, 1001〕、「訂單a-1002」→〔A1002〕。
- **命中**：訂單編號的詞序列，完整且連續地出現在備註的詞序列中才算命中。不做子字串比對，避免「A1」命中「A10」、電話或日期被拼出訂單編號。
- **編號強度**（以去掉分隔後的整串編號判斷）：
  - **強編號**：同時含英文字母與數字，且長度 4 以上（例如 A1001、SO1001）。命中尚未配對的訂單時，金額相同 → `matched`；不同 → `mismatch`，依據說明列出差額。
  - **數字編號**：純數字且長度 4 以上（例如流水號 1001）。金額相同才 `matched`；不同視為沒有命中。
  - **短編號**：長度 3 以內，或只有英文字母（例如 12、115、TEST）。金額相同時列為 `candidate`（待確認）；不同視為沒有命中。避免日期、時間被當成訂單編號自動配對。
- 命中多筆不同的尚未配對訂單（例如一筆匯款寫了兩張訂單）：全部列為 `candidate`，不進入層級 ②、③。
- 強編號只命中已配對的訂單（疑似重複付款）：不進入層級 ②、③，列為「不明入帳」，避免被建議成無關的訂單。
- 配對結束時，對到「已被其他入帳確定配對」之訂單的候選一律移除，確保一筆訂單最多只有一筆有效配對。

### 5.2 層級 ②：帳號末五碼＋金額

入帳末五碼等於訂單末五碼，且金額相同：恰好一筆 → `matched`；多筆 → 全部列為 `candidate`，不進入層級 ③。

### 5.3 層級 ③：金額＋日期

金額相同，且入帳日期在訂單日期當天到之後 N 天內（N 預設 7，上傳時可調整）→ 全部列為 `candidate`。符合的訂單超過 5 筆時判斷價值太低，不列候選，該入帳列為「不明入帳」。

### 5.4 確認與排除

- 候選對到的訂單仍可能出現在其他入帳的候選中，由使用者確認時決定。
- 確認某個候選後：同一入帳的其他候選、以及同一訂單在其他入帳的候選，自動改為 `rejected`；若被自動排除的候選所屬入帳因此沒有任何候選，即成為「不明入帳」。
- 排除某個候選後，只改該候選的狀態。只有待確認的候選可以確認或排除。

### 5.5 效能

層級 ① 以「編號 → 訂單」查表，層級 ② 以（末五碼、金額）索引，層級 ③ 以金額分組並依日期二分搜尋；2 萬筆入帳對 2 萬筆訂單需在數秒內完成。

## 6. 網頁流程

```
首頁（對帳工作清單＋上傳表單＋「載入範例資料」）
   │ 上傳銀行明細與訂單檔（可調整日期容許天數）
   ▼
自動辨識格式 ── 辨識不出 ──▶ 欄位對應頁（指定每個欄位，可命名儲存）
   │                                │
   ▼◀───────────────────────────────┘
對帳結果頁（摘要／待確認／金額不符／未收款／不明入帳／已配對／略過的資料列）
   │  待確認：每筆候選有「確認」、「排除」
   ▼
下載 Excel 報表（反映目前的確認狀態）
```

- 結果頁摘要：入帳筆數與總額、訂單筆數與總額、已配對筆數與配對率、待確認件數、金額不符件數、未收款筆數與總額、不明入帳筆數與總額。
- 「格式設定」頁：列出內建格式與使用者建立的格式，可刪除使用者建立的格式。
- 欄位對應頁需要暫存剛上傳的兩個檔案：存在伺服器的暫存資料夾，以隨機 token 識別，完成對帳或超過 1 小時即刪除。

## 7. 錯誤處理

| 狀況 | 處理 |
|---|---|
| 檔案讀不了（損壞、不是 CSV／Excel、編碼無法判斷） | 上傳頁顯示錯誤訊息 |
| 辨識不出格式 | 進入欄位對應頁 |
| 欄位對應缺少必要欄位 | 欄位對應頁顯示錯誤 |
| 某列日期或金額無法解析 | 跳過該列並記錄列號與原因；結果頁與報表都列出 |
| 檔案超過 5 MB 或 2 萬列 | 拒絕並說明 |
| 訂單編號重複 | 只保留第一筆，其餘記為略過的資料列 |

## 8. Excel 報表

工作表：摘要、已配對、待確認、金額不符、未收款訂單、不明入帳、略過的資料列。標題列粗體並凍結；金額欄使用千分位格式；「金額不符」「未收款」「不明入帳」以淡紅底色標示，「待確認」以淡黃底色標示。檔名：`對帳報表_工作{id}_{YYYYMMDD}.xlsx`。

## 9. 設定

| 變數 | 說明 |
|---|---|
| `DATABASE_URL` | 預設 `sqlite:///data/reconcile.db` |
| `RETENTION_DAYS` | 對帳工作保留天數，預設 90；0 表示不自動刪除 |
| `UPLOAD_DIR` | 暫存資料夾，預設 `data/uploads` |

到期刪除在服務啟動時與每次開啟首頁時執行。

## 10. 範例資料

`scripts/make_samples.py` 以固定亂數種子產生虛構資料到 `samples/`：示範銀行 A（CSV，Big5，表頭上方有標題列，民國年日期）、示範銀行 B（xlsx）、示範電商訂單（xlsx）。範例需涵蓋：層級 ①、②、③ 的配對、多候選、金額不符、未收款、不明入帳、略過的資料列。

## 11. 測試

使用 pytest，不需要網路。重點：讀檔（UTF-8／Big5、標題列、xlsx／csv）、格式辨識、正規化（金額寫法、民國年）、配對規則邊界與決定性、確認後自動排除、報表內容、web 流程（上傳、欄位對應、確認／排除、下載、範例資料、到期刪除）。
